Classroom Help Button

Today you will build a small micro:bit device that lets you ask for help without calling across the room. You will write the code, test it, let a partner try it, then make it better.

What you will make Press button A for I'M STUCK. Press button B for CHECK THIS. If you finish early, add A + B for CAN I TALK?

How the lesson runs

Starter — How would you ask for help? 8 min
Main 1 — Build your help button 22 min
Main 2 — Try it on a real micro:bit 23 min
Extension — Add "Can I talk?" optional
Plenary — What worked and what changed? 7 min
Finish — Check your work and export your PDF —

Ideas for making it clearer

        

          

            
If the message was unclear

            
display.scroll("CHECK") → display.scroll("CHECK THIS")

            
display.scroll("HELP") → display.scroll("I'M STUCK")

          

          

            
If the message took too long

            
Use a shorter message: display.scroll("STUCK") instead of display.scroll("I NEED SOME HELP")

            
Or reduce sleep(1000) to sleep(500)

          

          

            
If the two choices looked too similar

            
Use different pictures: Image.CONFUSED and Image.YES

          

          

            
If your partner did not know it had worked

            

          

          

            
If the screen became confusing

            
Use display.clear(), or go back to the starting screen with display.show("?")

          

          

            
If a choice no longer feels right

            
Replace it completely. You are allowed to change your mind after testing.

This lesson at a glance

    

      

        
Key topic

        
Python input, processing and output with a micro:bit

      

      

        
WAGBA

        
Create, test and improve a micro:bit help button using Python.

      

      

        
Knowledge — you will know

        
    
          
  • pressing a button provides an input
    • 
          
  • the program checks which button was pressed
    • 
          
  • the picture or message is the output
    • 
          
  • code can be tested in a simulator before being sent to a micro:bit
    • 
          
  • a Python file needs a clear and recognisable filename
    • 
        

      

      

        
Skills — you will be able to

        
    
          
  • edit a short micro:bit Python program
    • 
          
  • test buttons A and B in the simulator
    • 
          
  • save a Python file correctly
    • 
          
  • send working code to a physical micro:bit
    • 
          
  • collect feedback from a partner
    • 
          
  • improve the project after testing
    • 
        

      

      

        
Understanding — you will understand

        
    
          
  • input, processing and output work together
    • 
          
  • a simulator helps find problems before using a physical device
    • 
          
  • a message must make sense to the person using it
    • 
          
  • testing and improving are normal parts of creating a project
    •
