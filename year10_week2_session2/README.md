## Starter recap and presentation (10 September 2026)

- A short reading introduces identifiers, values, assignment, data types and meaningful naming before the five original starter questions.
- Questions follow one column, with 18px-equivalent body text, larger code, explicit answer instructions and optional hints. The code is repeated beside question 5 to avoid requiring a student to remember or scroll back to it.
- The suggested seven minutes includes the reading; it is not a countdown. Students may use the recap and ask for help at any point.
- Reduced-motion preferences are respected. These supports are options, not a claim that all autistic students need the same design; agree useful adjustments with the individual learner.
- The five answer keys and existing browser storage are unchanged. The PDF includes every starter answer, clearer question labels and the shared program needed to interpret questions 4 and 5. No automatic grading has been added.

Design references: [W3C cognitive accessibility: clear step-by-step instructions](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p07-step-instructions/) and [Python's identifier rules](https://docs.python.org/3/reference/lexical_analysis.html#names).

## Main Activity 2: guided code tutor (10 September 2026)

- Part A now introduces the Code Quest scenario before a student-controlled, numbered line tutor. Previous/Next and a line selector move its pointer; explanations never autoplay. A student chooses when to reveal an explanation, a before/after value, symbol help, or the complete stored values and output so far.
- The tutor is a **prepared trace of the supplied 19-line example**, including blank lines. It is not a Python interpreter and does not execute pasted code. Every selected line shows the state reached by following the original program from line 1. The raw copy button excludes numbering and pointers.
- Part B provides ten single-step instructions, relevant original line numbers, optional adaptation examples and concrete checks to carry out in the student's own IDE. Students may use different valid names and values. Ticking a check does not advance the guide, and no step is locked.
- Checks are **manual student reports**, not automated validation or marks. The teacher should review the actual code, output and screenshots. “Not checked” may mean unfinished checking, not necessarily unattempted work.
- All original answer identifiers remain unchanged. Each profile autosaves its tutor position, explanations opened, current checklist step and checks alongside existing responses. Teacher preview remains separate. Clearing a profile also clears its tutor record.
- Complete PDF export includes the supplied program, support-use record and all ten checklist statuses, as well as the existing answers, code and images. Teams submission instructions remain at the end.
- The practical uses one reading column, 18px-equivalent body/code text, clear text labels as well as colour for the pointer, optional detail, keyboard-operable controls and no timed progression. These are available to everyone; agree the most useful support with the individual student rather than assuming a single autistic learning profile.

Deploy **index.html, styles.css, app.js, tutor.js and assets/** together. There is no build step and no new external runtime dependency. This update does not publish or deploy the site.

Teaching rationale: program comprehension and tracing before adaptation reflect [Raspberry Pi Foundation computing pedagogy](https://www.raspberrypi.org/teach/pedagogy/). Single, adjacent instructions and user-paced checks follow [W3C cognitive accessibility guidance](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o4p07-step-instructions/). The Sites skill's readability guidance informed the single-column layout and larger text; the existing static deployment was preserved.

## Types of learning and learning pit stop

- **After the five starter questions, before Main Activity 1:** students review six statements (two each for Knowledge, Skills and Understanding). They distinguish prior learning, prompted recall, new learning and uncertainty. The starter is not treated as evidence for untaught constants or every later skill. Knowing a definition is knowledge; performing a naming/assignment task is skill; explaining purpose and maintainability is understanding.
- Suggestions identify learning to clarify or practise, without counting already-secure definitions as gaps or assigning a fixed learner type. Students choose their own WAGBA target and record an example or a teacher discussion.
- **After Main Activity 2, before extension/plenary:** the same six statements show the earlier starting point. Each gets its own current stage: New learning, Consolidating, Treading water, Drowning/need help, or Not attempted yet. Topic-specific actions suggest supported practice or one of the existing extensions. A learner may need help with one topic while finding another easy.
- A help selection tells students to show/tell their teacher; this local app does **not** send a teacher alert. Self-reports are not scores or verified attainment. No automatic “mastery” label or progression lock is added.
- Sixteen new reflection fields autosave with the existing profile. Export includes all responses, the before/after comparison and the suggested next actions, including unfinished reflections. The original 42 core answer keys and tutor records remain unchanged; reflection completion is not added to the core-answer score.
- Suggested core pacing is 60 minutes: starter/recap 7 + learning focus 3 + Main Activity 1 18 + Main Activity 2 22 + pit stop 3 + plenary/export 7. Extensions remain optional early-finisher work; there is no countdown.
- Include **reflections.js** alongside index.html, styles.css, app.js, tutor.js and assets/ when manually deploying. The single-column presentation follows the Sites readability guidance; no new hosting service or dependency has been introduced.
