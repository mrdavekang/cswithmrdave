# Year 10: checkpoint review and FOR loops

Static lesson for OxfordAQA 9210, section 3.2.2. No framework, build step, account server or online Python interpreter. Open `index.html` locally, or place this whole folder in the existing GitHub Pages repository. No publication is performed by saving these files.

## 60-minute route

| Minutes | Activity |
| --- | --- |
| 0–5 | Do Now: integer input, comparison meaning, indentation |
| 5–8 | Types of Learning: identify a review focus; optional loop baseline |
| 8–23 | Main Task 1: paper checkpoint review and prepared explanation |
| 23–30 | Read and model: definite iteration and both notations |
| 30–37 | Main Task 2: predict and trace five tickets |
| 37–49 | Main Task 2: modify, run and test an input-controlled count |
| 49–54 | One optional extension |
| 54–57 | Learning Pit Stop |
| 57–60 | Plenary and export |

Protect review time. If corrections expose a prerequisite gap, use a scaffold in Main Task 2 and defer the optional extension. Count input is a positive integer by assumption. Validation, accumulators, WHILE, nested loops and step values are deliberately excluded.

## Before the lesson

1. Return teacher-marked papers. Give students only the question and marking points they need to review. Actual test questions and mark schemes are not distributed in this public app.
2. Print `resources/Year_10_Checkpoint_Review_Three_Routes.pdf`. Pages 1–2 are Build, 3–4 Strengthen, 5–6 Transfer. Each pupil collects one pair. The teacher preview can also export each pair separately.
3. Model one paper answer against its marking points before independent review. Do not turn example wording into an exact-match requirement unless the actual question requires an exact term or output.
4. Have the Python IDE ready, along with the pupil's agreed communication/pause routine.

The total /40 is optional. The chosen question's awarded/available marks suggest a route: no credit -> Build; partial -> Strengthen; full -> Transfer. These are not validated grade boundaries, fixed ability bands or automatic diagnoses. A student who has full credit but cannot yet explain should choose a more supported route. Teacher/student judgement overrides the suggestion.

On paper, collect question/marks, original response, credited/missing ideas, K/S/U focus, corrected or transfer answer, example/test, prepared explanation, evidence level and an actionable next step. The web only records metadata and self-reported paper progress. No typed checkpoint answer or reflection boxes are provided.

## Support and explanation

One predictable step at a time; persistent readable code; manually controlled pointer; optional scaffolds and sentence frames; private prepared explanation; choice to point, write or read before independent speech. The help card is shown locally, not sent to a teacher. Agree supports with the individual pupil; these features are not a clinical intervention and do not guarantee any particular response.

K/S/U evidence is recorded per target (not yet / with support / independently). Learning phases are separate (new learning / consolidating / treading water / drowning-needing help). These are formative self-reports, not grades or automatic verification of code.

## Saving and export

Name and class identify a notebook in this browser. IndexedDB is used, with localStorage fallback. No central tracker, real login, Teams connection or remote alert exists. Use a school-approved device/browser and export before changing devices. On shared devices, browser users should follow the school's data/privacy routine; a name is not a password.

The top-right Export PDF works at any stage. It includes all core prompts (unanswered ones labelled), saved answers, code, tests, self-check history, support choices, all attempted extension records and all uploaded or pasted images uncropped. Optional paper photos can be attached on the submission page. JSON Backup preserves editable data and images; Restore works with this lesson's backups. A browser storage failure displays an explicit backup warning.

Students must open their PDF, attach it to the correct Teams **assignment**, select **Turn in**, and verify the status there. Classwork/Files upload alone is not assignment submission. Hand in the physical review sheet as directed. No private test marks or student response exports are included in the distributed folder.

Teacher preview: name `teacher` (class optional), or `index.html?teacher=1`. All pages, guidance, projection view and blank-sheet exports are available. This shortcut is not access control; teacher notes contain only lesson models and general marking guidance, not the protected test paper/mark scheme.
