# Week 2 Session 3 — Input, Arithmetic and Conversion

Open `index.html` directly, or upload the entire folder to a GitHub Pages repository.

## Teacher preview

Enter `teacher` as the name. The class field can be left blank. Teacher preview responses are saved separately from student work, and the teacher banner includes controls for sample answers and clearing the preview.

## Student workflow

- First entry opens a short **Read first** page before Do Now: input and prompts, assignment to meaningful identifiers, string/int/float conversion, a line-by-line example and a TypeError explanation. Other error types are optional help.
- A verified short extract comes from the supplied OxfordAQA Student Book, printed p8 (PDF p12); the supporting teacher-written explanations reference printed pp8–9 and pp18–19. They are explicitly distinguished from quotations.
- Students choose **Continue to Do Now**, then work through Starter → Types of learning → Main Activity 1 → Main Activity 2 → Extension → Learning pit stop → Plenary. Suggested minutes: reading 4, starter 4, types of learning 3, main 1 18, main 2 22, pit stop 3, plenary/export 6 (60 total). Extension is for time remaining within practical work, not an extra compulsory allocation. No timer is imposed.
- Both reflection pages use six matched checks: input/stored data and operator meanings (Knowledge); input/conversion/output and prediction/testing/debugging (Skills); data-type choices and complete groups/remainders (Understanding). Students choose their own focus and support it with evidence. Counts are self-reports, not attainment scores, and unanswered checks are not treated as deficits.
- The pit stop compares starting points with current stages and provides topic-specific next actions. New learning, consolidating, treading water and drowning are not ranked or averaged. Not attempted is a separate option. Help requests are saved locally, not sent to the teacher.
- Existing saved page indices are migrated once to the new seven-page sequence without changing answers or evidence.
- Reading can be revisited from the navigation or starter without clearing answers. Existing saved answers and evidence remain unchanged; existing profiles see the new preparation once, then retain normal saved-page resumption.
- Starter questions appear in a single column with clear answer instructions and larger code text. Code-copy controls sit below the code so they cannot cover it.
- Supplied Python appears only in copyable code blocks. No Python runs inside the webpage.
- Students run, test and debug code in their own Python IDE.
- Written answers and pasted code autosave in the current browser.
- IDE screenshots can be pasted, dragged or selected. They are stored in the browser's local database.
- The progress indicator tracks the 37 core responses. Extension challenges are optional.

## PDF evidence and Microsoft Teams

The **Export complete PDF** button prepares one printable report containing:

- student name and class;
- Objective, WAGBA and Knowledge, Skills and Understanding;
- every answer from every lesson section;
- all pasted Python code;
- uploaded evidence images at their full aspect ratio;
- final Microsoft Teams submission instructions.
- a preparation navigation note (not a mark or proof that reading was understood).
- both reflection pages, including all choices, evidence, K/S/U counts, before-and-after comparisons and suggested actions.

Students choose **Save as PDF** in the print window and use the suggested filename. They should remain on the same device and browser until the PDF has been exported and submitted.
