How to use this guide

Every Gold question has inputs so large that simply trying every possibility will never finish in time. The skill is spotting the mathematical structure and choosing a technique that turns a slow loop into a fast one. This guide has two halves:

  1. Topic library — tutorial-style explanations of the advanced tools Gold relies on, with generic example code. The examples are not solutions to the questions.
  2. Hint map — each question reduced to its plain task, plus the topics most likely to unlock it. Click a pill to jump to the explanation.
Rules reminder: you may read this reference, but every line of code must be your own, and no AI tools are allowed. This page names techniques and patterns; the insight to apply them is what's being tested.

Why brute force won't fit

Always check the size of the input first — it tells you which techniques are even allowed.

Input sizeRoughly what fits in time
up to ~10⁶a single pass, or sorting
up to ~10⁵an n·log n or even n·√n method
up to a few thousandan n² double loop
10¹², 10²⁰, "last 9 digits"no per-item loop — you need maths: dynamic programming over structure (digits, length) or a closed formula
When you see a bound like 5×10²⁰ or "submit the last 9 digits", that is a strong signal the intended method counts cleverly (digit DP, a recurrence, modular arithmetic) rather than iterating over every value.

Big integers in Python

Python integers never overflow — they grow as large as needed. So 10²⁰ is fine to store; the problem is never the number itself, it's doing too many operations.

n = 5 * 10**20      # perfectly valid
print(n + 1)        # exact, no overflow

Dictionaries for fast lookups

A dictionary checks "have I seen this value, and how often?" in roughly constant time — far faster than scanning a list each time.

seen = {}
seen[key] = seen.get(key, 0) + 1   # count occurrences
if key in seen: ...                # instant membership test
Turning a "for every pair, check…" double loop into a "remember what I've seen in a dict" single loop is one of the most common ways to go from too-slow to fast.

Prefix sums (1D)

A prefix-sum array lets you get the sum of any slice instantly, after one setup pass.

nums = [1, 1, 3, -1]
prefix = [0]
for x in nums:
    prefix.append(prefix[-1] + x)
# sum of nums[i..j] (inclusive) = prefix[j+1] - prefix[i]

Counting subarrays that sum to k

The classic pairing of prefix sums with a dictionary: a slice sums to k exactly when two prefix sums differ by k. Count how many earlier prefix sums equal running - k.

from collections import defaultdict
count = 0
running = 0
seen = defaultdict(int)
seen[0] = 1
for x in nums:
    running += x
    count += seen[running - k]   # slices ending here that sum to k
    seen[running] += 1

2D prefix sums (rectangle sums)

The same idea in two dimensions: after one setup pass you can get the sum of any rectangle in constant time.

# P[r][c] = sum of the rectangle from (0,0) to (r-1,c-1)
# sum of rectangle (r1,c1)..(r2,c2) inclusive =
#   P[r2+1][c2+1] - P[r1][c2+1] - P[r2+1][c1] + P[r1][c1]
Common trick: to count rectangles with a given sum, fix a pair of rows, collapse the columns between them into one row of partial sums, then reuse the 1D "subarray sums equal to k" method on that row.

Dynamic programming & memoisation

DP solves a big problem by combining answers to smaller sub-problems, storing each sub-answer so it's computed only once.

from functools import lru_cache
@lru_cache(maxsize=None)     # remembers results automatically
def solve(state):
    if base_case(state):
        return base_value
    total = 0
    for choice in options(state):
        total += solve(smaller_state(state, choice))
    return total
Ask yourself: "what's the smallest piece of state that fully describes a sub-problem?" Good state design is the whole game in DP.

Recurrences & counting structures

"How many valid things of size n are there?" usually has a recurrence: build size n from smaller valid pieces. Grammar-style rules (an expression is a digit, or a±b, or (a)) translate directly into a counting recurrence over length.

# count[L] = number of valid items of length L
# built by summing over the ways to split L into valid parts
count = [0] * (N + 1)
count[1] = base_count
for L in range(2, N + 1):
    # add up each rule that can form length L from shorter pieces
    pass
When the rule is "a OP b" you typically loop over where the split happens and multiply the counts of the two parts; brackets add a "wrap a length-(L-2) item" term.

Modular arithmetic (keeping only the last digits)

"Submit the last 9 digits" means work modulo 10⁹: take % 1_000_000_000 after every addition and multiplication so numbers stay small and the last 9 digits stay correct.

MOD = 10**9
total = (total + part) % MOD
prod  = (a * b) % MOD
Apply the mod throughout the computation, not just at the end — otherwise intermediate values explode. (Python could store them, but it would be slow, and subtraction needs care: (x - y) % MOD keeps the result non-negative.)

Digit manipulation

n = 1071
digits = [int(ch) for ch in str(n)]   # [1, 0, 7, 1]
digit_sum = sum(digits)               # 9

# or without strings:
s = 0
while n > 0:
    s += n % 10     # last digit
    n //= 10        # drop it

Digit DP — counting up to an enormous N

When N has 12 or 20 digits you cannot loop from 1 to N. Digit DP builds numbers digit by digit and counts how many satisfy a property, carrying a little state (position, a "still tight against N's prefix?" flag, and whatever the property needs, e.g. the digit sum so far).

from functools import lru_cache
digitsN = [int(c) for c in str(N)]
@lru_cache(maxsize=None)
def count(pos, tight, running_state):
    if pos == len(digitsN):
        return 1 if property_satisfied(running_state) else 0
    limit = digitsN[pos] if tight else 9
    total = 0
    for d in range(0, limit + 1):
        total += count(pos + 1,
                        tight and d == limit,
                        update(running_state, d))
    return total
This counts in time proportional to (digits × states × 10), not to N itself — so 10²⁰ becomes easy. Decide carefully whether you're counting in [1, N) or [1, N].

Number theory: gcd and friends

from math import gcd
gcd(12, 18)              # 6
pow(a, -1, m)            # modular inverse of a mod m (Python 3.8+)
pow(base, exp, m)        # fast (base ** exp) % m
A value x is reachable by repeatedly adding t modulo a exactly when x is a multiple of gcd(t, a). gcd is the backbone of "which states can I reach by stepping?" questions.

Linear congruences & the Chinese Remainder Theorem

"Can pressing buttons (each any number of times) hit a target colour on every light at once?" is a system of linear congruences: find integers k₁…kₘ with, for each light j, Σ kᵢ·tᵢ,ⱼ ≡ xⱼ (mod aⱼ). The buttons are shared across lights, so the equations are linked.

# a single congruence k * t ≡ x (mod a) is solvable iff
# x is divisible by gcd(t, a). CRT combines independent
# congruences with different moduli into one.
from math import gcd
Useful sub-questions to think through on paper: for one light, which targets are reachable? When several equations share the same unknowns, what consistency condition links them? gcd, modular inverses and CRT are the tools, plus careful case analysis.
