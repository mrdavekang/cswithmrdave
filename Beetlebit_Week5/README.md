# Beetle:bit Week 5 — Build Bench

GitHub Pages: https://mrdavekang.github.io/cswithmrdave/Beetlebit_Week5/

Static card-based KS2/KS3 assembly support. Choose a physical starting point, build a small section and record observations of the actual robot. No school-template stages. No powered-test approval by the app.

Typing `teacher` as the name enables an unsaved preview, not authentication. Progress is device-local and profile-specific. JSON backups restore on other devices. Matching same-browser Week 4 notes are imported as reported history, never verified Week 5 checkpoints.

Sources:

- Uploaded February 2026 Cytron booklet, pp.6–7,9–23,38. Screenshots reused from Week 4. Full booklet linked, not republished as a 224 MB download.
- Official assembly video https://www.youtube.com/watch?v=uMzD8UFlGDc, linked by https://beetlebit-hub.cytron.io/chapter-resources/beetlebit-setup-guide. No fabricated timestamps.
- Supplemental photos https://my.cytron.io/tutorial/robo-grip-mini-installation-guide-using-1-servo-motor. Its hardware differs. Flagged steps14,21,23,24,25,27 must be checked against actual kits by the teacher.
- Bolt measurement https://www.accu.co.uk/p/123-how-to-measure-a-screw. Technical SVG is schematic, not life-size or a hardware photo.

Family photos cannot identify individual lengths. Prepare measured teacher-kit samples and resolve revision differences before pupils tighten flagged joints. Teacher power/calibration inspection is physical, outside the app.

Student text escaped. Backups size-limited, cleaned to allowed fields, criteria and step ranges, with confirmation before replacing a profile. No remote pupil database, analytics or unsolicited uploads. YouTube loads only on request.

No build or installation required. Preview with a local static server. `check.cjs` uses the workspace’s existing jsdom for focused checks.
