# Year 10 · Week 3 Session 1 — From Problems to Algorithms

Static lesson for OxfordAQA International GCSE Computer Science 9210. Open `index.html` locally or host this folder on GitHub Pages. No build, server, Python runner, online editor or framework is required. Keep `index.html`, `app.js`, `styles.css` and `assets/` together.

## Scope and route

Sequence, decomposition and abstraction, applied through familiar Python input, conversion, assignment, multiplication and output. This does not introduce flowchart construction, formal trace tables, loops, selection or subroutines.

60-minute guide: introduction/recap 3; Do Now 7; types of learning 4; Main Activity 1 16; Main Activity 2 20; pit stop 3; plenary 7. The optional paper extension is for early finishers within practice time, not additional compulsory minutes.

The same Riverside sponsored-run brief continues from selecting information and decomposing tasks to implementation and tests. The numbered notebook tutor is a fixed worked explanation, not a Python interpreter. Students run and test code in their own IDE.

## Teacher preparation

- Enter `teacher` in the name field to preview all stages with model guidance expanded. This is a convenience mode, not authentication. Student data is not remotely accessible.
- Prepare **June 2023 OxfordAQA 9210/2, Q02.1–02.3, printed page 3 (5 marks)** and the official mark scheme. Hand out only these selected parts. The website intentionally contains no answer fields or exam answer key for the extension.
- Optional recognition-support alternative: November 2023 Q01.1 (2 marks). This is not a second compulsory task.
- “Ready for my paper” is a local screen signal. Students must also physically raise their hands. No notification is sent. Received/handed-in buttons are self-reports, not marks.
- The sequence checker accepts all eight valid orderings of the five tasks. It checks dependencies rather than one exact answer sequence.
- Automatic feedback checks three starter roles, seven information classifications and sequence validity only. Written reasoning, code correctness and test results require student/model comparison or teacher review. No aggregate attainment score is generated.

## Reading references

OxfordAQA IGCSE Computer Science textbook, printed pages (PDF viewer pages are four higher): p. 8 input/assignment/sequence; pp. 18–19 conversion recap; p. 88 decomposition and further subdivision; pp. 98–99 algorithms/implementation; pp. 100–101 abstraction and relevance to purpose. The readings in this app are teacher-written summaries, not purported verbatim extracts. Nearby subroutine and loop activities are deliberately not assigned.

## Reflection and access

Knowledge, skills and understanding remain visible with WAGBA. Six matched targets (two per category) connect the starting reflection to the post-extension pit stop. Counts describe self-reported independence/support/new learning and current phases, not verified marks. Stages are not a ranked scale; unanswered and not-attempted are not treated as wrong. Suggested next steps refer to the actual lesson tasks.

Single reading column; Raleway locally hosted; restrained colours; thin borders; selectable code; 17px code; keyboard navigation; manual line pointer; no timer or forced-correct progression. Students may revisit stages, export unfinished work and ask for help without completing all fields.

## Saving, evidence and PDF

- Text, choices and handover status use local browser storage. Original-resolution PNG/JPEG/WebP screenshots use IndexedDB, with explicit warnings if storage fails. Up to six screenshots, maximum 8 MB per image.
- Export uses the browser's **Print → Save as PDF**. It includes every registered answer, first checked/revealed attempts, current tests, matched reflections, paper handover and uploaded screenshots. Long text wraps rather than clipping. Missing images are explicitly flagged.
- Students should preview all pages, save the PDF, attach it to the correct Teams assignment and select **Turn in**. The site does not submit to Teams automatically.
- JSON backup download is an additional copy of work and images, not a student-readable substitute for the PDF. This version does not offer automatic backup import.
- Browser storage is not permanent or cross-device. Private browsing, clearing site data, changing browser/device, or moving between file and hosted origins can lose access to it. Export before moving. The app has no remote database or live teacher dashboard.
- Existing v1 work on the same browser origin is migrated into v2 without deleting the old key. Earlier fields and scores are retained and clearly labelled in the report, not silently regraded. Teacher preview uses a separate storage key. Changing student identity starts a fresh record after archiving the previous record locally; export before doing so.
