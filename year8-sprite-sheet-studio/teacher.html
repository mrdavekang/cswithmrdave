Teach the expression loop

One body, different faces. The goal is to explain how a program orders and times the frames, not to draw a brand-new character.

Stage timer

05:00

  1. 00–04 · Mission and learning goals. Play the model; name what students will remember, practise and explain.
  2. 04–07 · Do Now. Students identify which part changes when only the eyes change.
  3. 07–10 · Types of Learning. Try the three checks. Use answers to decide whether to model vocabulary, duplication or alignment again.
  4. 10–14 · Frame model. Project the worked example. Ask: “What would you fix if the body jumps?” Listen for alignment, not speed.
  5. 14–29 · Main Task 1. Demonstrate Duplicate frame → Face → two pixel changes. Check three distinct expressions. Students without yesterday’s work use Garden Guide.
  6. 29–33 · Loop model. Project the timing demo. Get a prediction before playing both speeds. Frame order is the same; each picture is shown for less time.
  7. 33–48 · Main Task 2. Model one sprite with three costumes. Scratch is the default; use Python if Tkinter already works. Ask students to watch two loops and record one timing or order test.
  8. 48–52 · Learning Pit Stop. Review the KSU evidence, then ask students to choose a phase and explain why. A sheet alone is not evidence that a coded loop ran.
  9. 52–56 · Go Further / finish core. Fast finishers try Timing Director and compare both versions. Help others finish their core animation.
  10. 56–60 · Plenary and submission. Collect native sheet, evidence note and .sb3 or .py. The 30-correct review can be completed as follow-up.

What to look for

  • Frame count: at least three distinguishable expressions, one aligned character.
  • Technical model: one sheet and individual frames; native dimensions are (16 × frame count) by 16.
  • Programming: deterministic start and visible loop, with a deliberate delay.
  • Reasoning: one observation comparing before and after a timing/order change.
