# Week 1 Session 3 — From a plan to a program

A single-file, static Year 10 OxfordAQA 9210 lesson. Open `index.html` in a modern browser or publish this folder through the existing GitHub Pages workflow. No installation, build, server, Vercel project or online Python runtime is required. The optional Google Fonts request loads Raleway; the lesson falls back to Arial when offline.

## Teaching sequence (60 minutes)

| Stage | Minutes | Evidence |
|---|---:|---|
| Starter | 6 | Predict quiz score, identify processing, check a run |
| Types-of-learning pitstop | 3 | Connect knowledge, skills or understanding to one next action |
| Main activity 1 | 14 | Read and match a plan to code; explain implementation |
| Main activity 2 | 23 | Learn three pseudocode notations; trace, translate in an IDE, test |
| Current-phase pitstop | 4 | Identify current experience and a practical next step |
| Plenary and PDF | 10 | Three exit checks, reflection, evidence export and Teams submission |

Ten optional extensions are available for early finishers within working time and for later return. They are not ten additional compulsory tasks. They use only sequence, input, output, variables, assignment and arithmetic. They include adaptation, tracing, debugging, sequencing, comparison and independent design.

## Learning and accessibility

- Persistent WAGBA and K/S/U, predictable navigation, single-column activities and no timer or leaderboard.
- Optional one-task-at-a-time view, progressive hints, copyable scaffolds, syntax explanation and a manually stepped trace.
- Short automatically checked questions give specific feedback and retain each attempt. Answer completion is distinct from correctness. Written responses and Python programs require teacher review.
- Students run Python in their own IDE. Textareas store code; they do not execute or automatically grade it.
- Both school learning pitstops link reflection to this lesson. “Drowning” is paired with “I need help”; it is a task-specific reflection, not an ability label.
- Help choices are private to the browser/report and do not alert the teacher. Students must use an agreed classroom signal. Use individual support plans and offer oral/pointing responses where appropriate, recording brief evidence afterwards.
- Built-in readings are original summaries with textbook references: printed p. 10 / PDF p. 14, and printed pp. 12–13 / PDF pp. 16–17. Teacher notes include specification and pedagogical research links.

## Teacher preview

Enter `teacher` as the name; class can be blank. All pages are open. “Fill blank fields with examples” only fills blank teacher fields, never student profiles, and does not fabricate checked-answer histories. The reference test results are explicitly labelled as examples, not student runs. This is a preview shortcut, not authenticated access control. Students can navigate freely too.

## Records, screenshots and PDF

- Answers, check attempts, hint usage, learning reflections and help requests save locally in browser storage. Screenshots use IndexedDB and are not sent to a server.
- PNG/JPEG/WebP images up to 20 MB each retain their source pixels (no automatic lossy compression). Browser storage capacity varies. Failed saving is reported; export before leaving if warned.
- Choose **Export PDF** at any point, review the report, then **Print / Save as PDF**. Select A4. All current responses, unfinished work, check histories and evidence images are collected; long text and code wrap. Tall images fit within a printable page without cropping, so inspect legibility and use several focused screenshots when needed.
- Students open the saved PDF, check all pages, upload it to the correct Microsoft Teams assignment using **Add work/Attach**, and select **Turn in**. Export does not submit automatically.
- There is no central database or teacher dashboard. Devices/profiles are not authenticated. Avoid sharing sensitive information, and collect PDFs through Teams.
- Browser data is specific to the browser, device and origin. Changing hostname, browser profile or deployment origin will not move saved records. Keep the same name/class spelling to resume a profile. Clearing browser storage removes local work.

## Compatibility with earlier work

The redesign retains `w01s03-v1` storage keys, owner naming and the `OxfordAQA9210W01S03Evidence` database. Earlier responses are not silently mapped to new questions. They are retained and included in an **Earlier-version responses** section of the PDF. Existing screenshots remain associated with their original section. New prompts use separate keys. Export older work before changing device, browser or origin.

## Deployment

Only `index.html` is needed at `year10_week1_session3/index.html` in the existing repository. Commit and publish through your normal GitHub Pages process. This redesign does not change hosting configuration or publish automatically.
