Your thinking becomes more independent

This lesson moves from Know (recognise a plan, code and behaviour), to Apply (use the ideas in a new program), then Solve and improve (use evidence to change it). Your teacher may call these AO1, AO2 and AO3; you do not need to memorise those labels.

Learn · one shared scenario

The charity-points improvement cycle

A charity app should add a 5-point participation bonus. For an input of 20, it should display 25, but the current program displays 15. A computer scientist moves through these stages:

  1. Understand: the rule is points + 5.
  2. Plan: input points → add bonus → output total.
  3. Predict: 20 + 5 should give 25.
  4. Run: the current program actually gives 15.
  5. Check: compare 25 with 15 and inspect the calculation.
  6. Improve: change one operator, then test again.

Why a cycle? The new test tells you whether to finish or return to an earlier stage.

2 Planinput → add → output

5 Checkfirst difference: operator
6 Improvechange − to +, retest

Main Activity 2A · Guided to independent tracing · 17 minutes

Trace it—don’t guess it

Learning

What does tracing mean?

Tracing means pretending to be the computer. Begin at the first line. Complete exactly one instruction, update any changed value, then move to the next line.

  • Read one line.
  • Update the newest value.
  • Record the value or output.
  • Repeat until the program ends.
Worked example — watch the value change
lives = 3
lives = lives - 1
print(lives)
Line executedNew value of livesOutput
lives = 33—
lives = lives - 12—
print(lives)22

Important: = assigns a value. The newest value replaces the old value.

Main Activity 2B · Recognise, apply and explain · 13 minutes

Debug like a computer scientist

Learning
!

An error is evidence

Debugging is the process of finding, understanding and correcting problems. Read the clue before editing. Change one thing, rerun and compare the new result with what you expected.

A correct Python decision
if condition:
    indented_instruction

The colon ends the if line. The indented line belongs to that decision. This pattern will help you interpret the first error message.

Syntax error

The code breaks Python’s grammar, so Python cannot understand the instruction.

Clue: SyntaxError, often with a line number.

Runtime error

The code starts, but an operation becomes impossible while it is running.

Clue: an error such as division by zero.

Logic error

The code runs, but the result is different from the requirement.

Clue: expected £15, actual £25.

Level 3

Algorithm Architect

Written design
Design brief

A school club needs a sign-in program. It asks for a student's name and year group. If the name is blank, it displays an error. Otherwise, it displays a welcome message and the correct meeting room: Year 7–8 use Room A; Year 9–11 use Room B.

What is pseudocode?

A clear, language-independent description of an algorithm. It is not Python, so it does not need brackets, quotation rules or exact Python spelling.

  • INPUT receives data.
  • OUTPUT displays information.
  • IF … THEN / ELSE / ENDIF describes a decision.
  • Indent the instructions that belong inside a decision.
INPUT name
IF name is blank THEN
    OUTPUT "Enter a name"
ELSE
    OUTPUT "Welcome " + name
ENDIF
