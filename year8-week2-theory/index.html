    READ 1

    What are algorithms and programs?

    An algorithm is a precise, ordered set of instructions for completing a task or solving a problem. An algorithm can be written as numbered steps, pseudocode, a diagram or a flowchart. It does not have to be computer code.

    A useful algorithm must be clear enough for another person to follow without guessing. “Put it in the correct place” is unclear because the object and location are not identified. “Move the purple counter into the first square on the left” is precise.

    A program is an algorithm implemented in a programming language that a computer can execute. The algorithm is the plan; the program is one implementation of that plan.

    READ 2

    What are decomposition and IPO?

    Decomposition means breaking a large problem into smaller, manageable subproblems. Each smaller part can be planned and tested separately before the complete system is assembled. This makes complicated problems easier to understand, build, test and debug.

    Many computer systems can be described using input–process–output. Input is data or an event entering the system. Processing is what the system does internally. Output is the information or action produced.

    What is a flowchart?

    A flowchart is a diagram used to represent an algorithm. Standard shapes and arrows show the order of instructions, inputs, outputs, processes and possible paths. Flowcharts help programmers find missing or unclear steps before writing code.

    A flowchart is not a finished program. It is a visual plan that can later be implemented using a programming language.

    New extension idea: what is pseudocode?

    Pseudocode is a structured way of writing an algorithm using readable, code-like language. It is designed for people to understand and plan from; it is not tied to one programming language and is not normally executed directly.

    This example is for an automatic light, not the Smart Badge:

    START
READ light_level
IF light_level is low THEN
    DISPLAY "LIGHT ON"
END IF
STOP

    Keywords, indentation and one action per line make the logic easier to follow. You are only comparing representations here; pseudocode is not required in the core lesson.

    Now compare how numbered instructions, a flowchart and pseudocode communicate the same solution. Consider how easy each format is to read, change, trace and convert into a program.
