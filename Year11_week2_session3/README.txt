THE MOST IMPORTANT TEACHING CHANGE
Each main task has a "Ready for feedback" panel:
1. Learner pastes the current subroutine, even if incomplete.
2. Relevant lines are excerpted automatically; use Focus view when circulating.
3. Learner explains the expected result, actual result and uncertainty.
4. Save the attempt BEFORE editing. This keeps a dated copy.
5. Give one actionable prompt; learner records advice, change and retest.
6. Save correction & retest. Revisit to check evidence of improvement.
Short phrases are enough. Do not require every support field or several snapshots
from a learner who has already demonstrated understanding. Require the official
complete source and specified test evidence for an exam-marked submission.

2:30-3:00 OBSERVATION
If the lesson starts at 2:00, the visit covers Q06 feedback through export.
If the start differs, shift the above timings; do not rush a task for the observer.
Before coding, everyone can show 5/6/7 decisions on a mini-whiteboard. Ask why.
Use this evidence to choose who needs your first visit. Avoid calling correct
multiple-choice selections proof of understanding.
During a visit ask one focused question:
- Does your condition reject 6? Trace that comparison.
- Which statement changes factor before the next check?
- What happens for 6, then 7, then 3?
- What changed after feedback, and which retest proves it?
The teacher notebook has seven editable rows: boundary, re-input explanation,
observed test, feedback and follow-up. It is MANUAL and DEVICE-LOCAL; it does not
receive students' answers live. Export its PDF privately. Never put it in a
student submission or publish it to GitHub.
If several learners share a misconception, briefly model one iteration and
check everyone again. Use the independent plenary to decide next-lesson support.

EXAM CONTENT AND SUPPORT
Original question images and supplied files are unchanged.
Starter: Q01.1-Q01.3 = 3 marks.
Q05: source 4 + evidence 1 = 5 marks.
Q06: source 5 (maximum 4 if errors) + evidence 1 = 6 marks.
Optional Q07: source 8 (maximum 7 if errors) + evidence 1 = 9 marks.
Core official questions total 14; with optional Q07, total 23.
Learning checks and teacher-created practice are not official exam questions.
Teacher guidance is a summary, not a replacement for the official mark scheme.
These selected official questions are assessed under AO3. The school's knowledge,
skills and understanding language is not a one-to-one mapping to exam AOs.

Q05: use width then height AFTER loading. pattern gives width 5, height 9.
Exact output: The image has size 5 by 9 pixels
Q06: integer below 6. Reject factor > 5 / factor >= 6, display the exact error
and read a fresh integer inside the repeating block before stretching.
Exact error: Invalid input - please try again
Official test: load one; option 4; enter 6 then 3.
Additional tests: 5; and repeated invalid inputs 6, 7, 3.
Positivity and non-integer input handling are NOT extra official Q06 requirements.
Q07: a fresh copy; random 5-by-6 image; all 30 pixels in range 0 to 4 inclusive;
retain ordinary file loading. Official test: 1, random, 2.

Short extension: expose why a single if does not handle repeated invalid input.
If already secure: distinguish validity of 0/negative values under the stated
rule from conversion failure for hello; propose stronger requirements separately.
Long extension: original Q07. Do not delay the common plenary for it.
Plenary: identify equality-at-10 and missing re-input faults; fix; select tests.

EVIDENCE AND STORAGE
Each programming task has full-source text plus two image slots.
Choose, drag/drop, or focus a slot and paste an image. Upload PNG/JPEG where
possible. Evidence is resized to at most 2400 pixels on its longest edge.
Check screenshot readability before submitting. Keep inputs and outputs visible.
PDF contains current responses, code, boundary-check history, saved attempts,
feedback, corrections, retests, reflections and images. It allows partial work.
Autosave failure is shown explicitly; export before leaving if storage is full.
Old responses and uploads use the same storage key as the previous version.
Old exit-ticket answers are retained under Earlier saved responses, not inserted
into the redesigned question. Moving to a different address/browser/device does
not transfer local storage. Download before switching, and do not clear browser
data until you have submitted.
The activity percentage means RECORDING status, not accuracy, marks or mastery.
No student database, analytics, live class synchronisation or external API.
