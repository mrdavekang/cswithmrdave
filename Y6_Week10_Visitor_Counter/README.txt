YEAR 6 WEEK 10 — VISITOR COUNTER
Term 1.2 Robotics & Control Systems · 60 minutes

LOCAL STATIC / GITHUB PAGES ONLY
Open index.html in a normal browser, or serve this folder with a static server.
Upload the complete folder to the existing cswithmrdave GitHub repository when
ready. No npm, account, database, build process or ChatGPT Sites is required.
This delivery does not commit, push, publish or post anything to Teams.

LESSON FLOW
0–5     Do Now: exhibition purpose; retrieve input/output; predict a total
5–10    Types of Learning / WAGBA: Knowledge, Skills and Understanding,
        one goal per card with readiness/support choices
10–28   Main Task 1: create a new MakeCode project, make visitors, initialise
        and display its value, build A to add 1, then test three arrivals
28–42   Main Task 2: build B reset, test 3 → 0 → 1, discuss why clear screen
        is not a reset, and record a debugging/checking decision
42–45   Learning Pitstop — immediately after Main Task 2
45–52   Choose core practice, a visual extension, or supervised hardware work
52–56   Plenary explanation and Exit Reflections
56–60   Save HEX, download JSON, save report as PDF, hand in PDF + HEX

The default route contains 27 cards. There are 38 cards in total, including
optional challenges, USB hardware guides and reopen-at-home guides. Short
picture substeps use the same Next button, with only one guide shown at a time.
Extra cards enter the route only when selected. Teachers can adapt the timing.

LEARNING GOALS
Knowledge: explain that a variable stores a value that can change.
Skills: build, test and save a counter in MakeCode.
Understanding: explain why adding 1 and resetting to 0 do different jobs.

CORE PROGRAM
on start: set visitors to 0; show number visitors
on button A pressed: change visitors by 1; show number visitors
on button B pressed: set visitors to 0; show number visitors
The counter is manual. It counts button presses, not automatically sensed people.

SUPPORT AND ACCESS
- Names and classes are typed, not selected from a fixed class list.
- Pupils choose solo or pair working. Partner name is optional. Continue alone
  preserves shared work and never needs the absent partner to answer.
- One person operates while the other reads/checks; swap in Main Task 2.
- English remains visible. Mandarin or Korean support can be selected at any time.
- School K/S/U and Learning Pitstop posters are reused, not regenerated.
- Screenshots and block labels remain authentic English. Surrounding instructions
  and prompts provide bilingual support. A bilingual teacher should review local
  language preferences before teaching.
- Quiz choices are shuffled once per record and stay stable after refresh/restore.
- Correct answers do not lock progression. Short responses and reported faults
  are accepted. Help / skip records the need and moves forward without claiming
  the step was completed successfully.
- Plenary can be explained aloud. No pupil screenshots or evidence uploads here.
- Back/Next/help controls remain visible. Images are inline, not hidden in pop-ups.
- Name teacher opens all pages for review. This is open preview, not authentication.

MAKECODE IS THE PRACTICAL WORKSPACE
The prominent MakeCode button opens/reuses a separate named coding tab.
Pupils create their OWN project from New Project. The app does not load a finished
counter for them. A direct link is provided if the browser blocks the tab button.
The lesson cannot inspect, capture, pair or verify another service's editor.
Checks and test entries are pupil self-reports, not automated program assessment.
The real HEX and teacher discussion are needed to evaluate the actual code.

EXTENSIONS
1. Repair A that resets to 0 on every press and therefore always shows 1.
2. Count pairs: change by 2 and test three presses.
3. Add A+B: show string Welcome, then show number visitors, preserving the total.
Each has real code examples, a practical instruction, prediction and result record.
Students can choose one or all three. Hardware is optional, not a completion gate.
No Grove kit is required. Any future Grove activity needs supervision and checks
of compatible boards, modules and power; the 10 kits are not automatically used.

SAVING AND CONTINUING AT HOME
- HEX: real MakeCode program. Save it in MakeCode; reopen via Home → Import →
  Import File → choose HEX → Go ahead! Submit this to Teams.
- JSON: this lesson's answers, progress, quiz order, reflections and activity log.
  Download using Backup. Load it on the welcome page. Keep it for yourself.
- PDF: select Save my report as PDF; in the browser print window choose Save as
  PDF. Check the saved report and submit it with the HEX to the teacher's Teams
  assignment. The app does not claim that an assignment already exists or link
  to an invented Week 10 module. Teams screenshots can be added after creation.

Records save in this browser when storage is available. File-origin storage can
vary between browsers, so download JSON before moving device or changing where
the app is hosted. There is one current record per browser/origin. Back up before
starting a different pupil. A new record asks before replacing an existing one.
Storage can be cleared by the browser; downloaded JSON is the portable copy.
This app uses no analytics, credentials, remote fonts or server collection.
MakeCode and Teams are separate services and require network access.

VERIFICATION

short-answer acceptance, backup validation, shuffled choice persistence,
