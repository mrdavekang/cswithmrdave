Main Task 1 · 12 minutes

Make A ask a surprise question

The route can stay UP, RIGHT, DOWN for now. The change is which clue A asks you to remember.

Expected behaviourPlay several rounds. The question can be clue 1, 2 or 3. It must never ask clue 0 or clue 4. A repeat is allowed. The answer must match the selected stored clue.

1Find the A-button event

Return to your own Arcade editor, not the completed model. Find on A button pressed. It already sets answerIndex, reads route[answerIndex] and calls the prepared play block.

You will replace only the fixed 1 in the A event with a random range. Leave the indexed answer and teal play block underneath.

2Find the three small building blocks

Use Math for pick random and subtraction; use Advanced → Arrays for length of array. In the array dropdown choose route, not the four-value directions bank.

3Snap them into the range

  1. Put pick random 0 to … into set answerIndex to inside A.
  2. Set the upper limit to length of array route − 1. The subtraction wraps the length block.
  3. Keep set correctDirection to route get value at answerIndex next, then the prepared play route block.

2Replace one assignment inside on_a_pressed

Find def on_a_pressed():. Keep the global answerIndex, correctDirection line. Change the indented answerIndex = 1 to the random assignment below. Do not edit the generated initial value outside the function.

def on_a_pressed():
    global answerIndex, correctDirection
    answerIndex = randint(0, len(route) - 1)
    correctDirection = route[answerIndex]
    memoryCrew.play_round(route, correctDirection, answerIndex, clueMs)
controller.A.on_event(ControllerButtonEvent.PRESSED, on_a_pressed)

4Play, compare, improve

  1. Restart the simulator once so your edit takes effect. Press A and watch every clue.
  2. Read “Which was clue …?” Answer with the direction at that position. Remember: clue 1 uses index 0.
  3. Replay several times. The question need not change every time. Also deliberately try one wrong answer; it should give feedback and not add a point.

This is your observation, not an automatic check of the separate Arcade tab. You can keep learning even if you need help.

Different-data reference: three colours have valid indexes 0–2. This is a pattern to understand, not code to paste into the game.

colours = ["RED", "BLUE", "GREEN"]
chosen_index = randint(0, len(colours) - 1)
chosen_colour = colours[chosen_index]
Why do we use len(route) − 1, not len(route), as the greatest index?

Main Task 2 · 15 minutes

Make B build a new route

A random question is working. Now give the crew a new route to remember. B will clear the old route, then add random directions until there are exactly four.

The separate directions list is your bank of allowed words: UP, RIGHT, DOWN, LEFT. The route list stores the clues for this round. Do not empty the directions bank.

1Find B, then arrange the order

Find on B button pressed. Replace its fixed route list. The new order is clear → repeat adding → show. Keep show upgraded route route last and outside the loop.

After pressing BThe screen should say ROUTE UPDATED and show four lines, indexed 0, 1, 2, 3. Directions may repeat. B alone should not award points.

2Collect the B-event blocks

  1. Arrays: empty array; length of array; add value to end; get random value from.
  2. Loops: while false do. Logic: the comparison block; use its dropdown to choose <.
  3. Variables: set route to. You already have this assignment inside B.

3Build the B stack

  1. Set route to empty array. Remove slots using − until no values remain if your array starts with values.
  2. Add while length of array route < 4.
  3. Inside it, put route add value get random value from directions to end.
  4. Keep show upgraded route route after the loop. Compare your stack with the complete model.

2Replace the fixed route inside on_b_pressed

Keep global route. Replace the old fixed list assignment with the three-line loop below. The append line is indented one extra level inside while. memoryCrew.updated(route) lines up with while, so it runs after the loop.

def on_b_pressed():
    global route
    route = []
    while len(route) < 4:
        route.append(directions._pick_random())
    memoryCrew.updated(route)
controller.B.on_event(ControllerButtonEvent.PRESSED, on_b_pressed)

_pick_random() is MakeCode Arcade Python’s list helper. It is not standard Python’s random.choice, and this is not micro:bit MicroPython.

4See why the loop stops

Each append increases the length. The changing list length acts as progress towards the stopping condition; you do not need a separate counter here.

Before testIs length < 4?What happens?
0 cluesTrueAdd 1 → length 1
1, then 2, then 3True each timeAdd one on each repeat
4 cluesFalseLeave while; show route
If the simulator freezes, press its square Stop control. Check that append is inside while. Check that clearing the list is before while, not inside it. Do not use forever.

5Test the whole game and its score

  1. Restart once. Press B and inspect four stored indexes. Press B again: there should still be four, not eight.
  2. Press A. Watch all four clues, read the random question, then answer correctly. The score should increase by 1.
  3. Replay and deliberately answer incorrectly. Expect TRY ANOTHER ROUND and no score increase. Press A again to replay.

About scoring: the prepared engine compares the answer and updates Arcade’s score. You are building the route and question logic, not writing the scoring engine today. A starts a round; it must not give free points just for being pressed.

CHALLENGE 2

Fair expert mode

Your goal: Make clues faster and reward a correct answer with 2 points.

Where to edit: On start: clueMs and pointsPerWin, shown above.

Prove it worksEach clue is visible for about 0.6 seconds. Score 0→2→4 after two correct answers. A wrong answer keeps the same score.
CHALLENGE 3

Mystery-length missions

Your goal: Let B choose between 3 and 5 clues.

Where to edit: Inside B, before the while loop; Variables → Make a Variable → targetLength. Math → pick random.

Make this change: Set targetLength to pick random 3 to 5. Replace the loop’s fixed number with targetLength. Do not put the target choice inside while.

route = []
targetLength = randint(3, 5)
while len(route) < targetLength:
    route.append(directions._pick_random())
memoryCrew.updated(route)
Prove it worksEach B press makes exactly the chosen number: 3, 4 or 5. Repeats are allowed. A’s question stays within the current route.
CHALLENGE 4

Training mode you can actually test

Your goal: Prove your random code follows the stored data.

Where to edit: A’s random assignment and the starting route; no new blocks.

Make this change: Temporarily set A’s answerIndex to 0. Use a starting route whose first clue is LEFT. Restart; A must ask clue 1 and accept LEFT. Then test the final index. Restore the random expression afterwards.

answerIndex = 0  # temporary first-index test
# Then test len(route) - 1. Restore afterwards:
answerIndex = randint(0, len(route) - 1)
Prove it worksBoth boundary tests accept the current stored clue. Restored random mode stays in range. This tests rules, not a guaranteed sequence of random results.
CHALLENGE 5

A route with no adjacent repeats

Your goal: Stop two identical directions appearing next to each other.

Where to edit: B’s loop. Variables → newClue; Logic → if, or and not-equal; Arrays → get value at / length.

Make this change: Inside while, store get random value from directions in newClue. Append only if route is empty OR its final element is not newClue. Keep the while limit at 3–5.

route = []
while len(route) < 4:
    newClue = directions._pick_random()
    if len(route) == 0 or route[len(route) - 1] != newClue:
        route.append(newClue)
memoryCrew.updated(route)
Prove it worksUP, LEFT, UP is valid; UP, UP, LEFT is not. A repeated direction can still appear later. The list still reaches its target length.

For Challenge 5, the first condition protects the empty list before reading its last element. Arcade may add global newClue if you create a shared variable; keep generated declarations. Ask for an explanation if the nested condition is new.
