Controls students will use

Run PythonExecutes edited Python in a fresh worker and plays back the recorded drawing actions. Every run resets to the question's starting position, facing direction and pen state. Ctrl/Command + Enter also runs.
StepRuns the program if needed, then reveals one Turtle action at a time. It highlights the responsible editor line. This is drawing-action replay, not a general debugger; print(), calculations and comments do not each create a drawing step.
StopTerminates computation or pauses playback immediately. Draft code is retained. A new Run starts again.
Reset codeReturns that question to its supplied commands after confirmation. It does not erase the learner's original prediction or a separately kept PDF test.
PlaybackSlow, normal, fast or instant. Use this rather than t.speed() to control the classroom animation.
Grid / undrawn travelGrid is a teaching overlay. Dashed undrawn travel is off by default; it can show pen-up movement but is not part of the actual drawn line.
Expand editorOpens a larger workspace while staying in the lesson. Close it or press Escape to return. On narrower screens, View drawing and Back to code move between the stacked panels.
Touch keyboardInserts commands, brackets, commas, minus signs and indentation. The text editor also supports ordinary typing, Enter indentation and Tab/Shift+Tab.
Python consoleShows print() output and readable errors with the relevant student code line. Correct the code and run again.

Same PDF, better evidence

After a successful run, students can write what they noticed and choose Keep this test in my PDF. The report contains the executed code, actual output image, starting/final state and that observation. They may keep up to three short tests. There is no additional compulsory file or Teams submission.

The kept snapshot is deliberate: editing the code afterwards does not silently replace it. Run the new version and choose Update kept test to change the snapshot, or Remove kept test to remove it. Kept tests are limited to 35 short lines / 2,000 characters so report sections fit safely. The optional Save .py exports full editor code with setup, but some classroom-specific adapter behaviour may differ from desktop Turtle.

Finish Python experiments before preparing the final PDF. Substantive changes after preparation invalidate that PDF and reset local submission confirmations, just like changes to other lesson answers.

What runs here?

The local Skulpt interpreter evaluates the Python code. Variables, arithmetic, print(), conditions, loops and functions work. The custom Turtle adapter produces canvas drawing events. It supports the subset below; this is not a full desktop Python/Tkinter installation.

AreaExamples
Movementt.goto(x, y), t.forward(d), t.backward(d), t.setx(x), t.sety(y), t.home()
Turning / queryingt.left(a), t.right(a), t.setheading(a), t.position(), t.heading(), t.xcor(), t.ycor(), t.isdown()
Pen / colourt.penup(), t.pendown(), t.pensize(3), t.color("blue"), t.pencolor(...), t.fillcolor(...)
Drawingt.circle(30), t.dot(8), t.write("Hello"), t.begin_fill(), t.end_fill(), t.clear(), t.reset()
Turtlesturtle.Turtle(), basic built-in shapes, show/hide, module-level commands and common aliases such as fd, bk, rt, lt, pu and pd.
Screen subsetBackground colour and a small compatibility subset. Responsive layout controls screen size; mainloop()/done() return without opening another window. Titles are not a separate native window.

Not provided: desktop Tkinter, Turtle keyboard/mouse event callbacks, external images, package installs, input() prompts or external network requests from student Python. Circle rendering is polygonal and some visual details differ from desktop Turtle. An unsupported command should produce a helpful error rather than be treated as valid drawing code.

Example for teacher demonstration

distance = 50
for side in range(4):
    t.forward(distance)
    t.left(90)
print(t.position())

This optional example shows that it executes Python constructs rather than matching fixed numeric commands. The core lesson does not require a loop.

Limits and school-device check

The classroom editor caps code at 200 lines / 12,000 characters, drawing actions at 800 and console output at 12,000 characters. Time limits and a disposable worker protect the lesson from ordinary endless loops. These limits are not a guarantee against deliberately hostile code. The app is a local formative-learning tool, not a secure examination or connected grading system.

The interpreter and PDF libraries are included locally, with no runtime CDN dependency. Host the entire folder. School policies must permit Blob workers and Skulpt's generated JavaScript functions. Check Run, Step, Stop and PDF saving on the actual school devices; Chromium viewport checks are not native Safari or Android tests. Teams and Gimkit still need their own working links and authentication.

To upgrade an existing deployment, keep your already-configured config.js; replace all other app files together. Name teacher still enables review/demo mode and bypasses prediction gates. It is not authentication.
