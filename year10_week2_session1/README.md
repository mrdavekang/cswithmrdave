# Week 2 Session 1 — Choosing data types

Static, single-file Year 10 OxfordAQA International GCSE Computer Science (9210) lesson. Open `index.html` or keep it in the existing `year10_week2_session1` GitHub Pages folder. There is no build step, framework, account service or Python runtime in the page. Python is run in students’ own IDEs.

## Teaching sequence: 60 minutes

| Stage | Time | Purpose |
| --- | --- | --- |
| Starter | 5 min | Three low-stakes predictions about notation and printed appearance. |
| Types of Learning | 3 min | Identify knowledge, skills and/or understanding; select starter evidence and a next action. |
| Main Activity 1 | 16 min | Read a concise type reference, study a worked example, choose types for five club requirements and explain one choice. |
| Main Activity 2 | 24 min | Study a complete `type()` example; predict and run two investigations; build and test a club profile. |
| Learning Pit Stop | 3 min | Select a current learning phase, cite evidence and choose a next step. |
| Extension | Optional | Ten original challenges in Consolidate, Apply and Stretch routes. Use spare time or later practice; do not require all ten in this hour. |
| Plenary and export | 9 min | Two independent selections, one explanation, next practice focus and PDF submission. |

WAGBA and Knowledge/Skills/Understanding are present above every stage, including on narrow screens. Reading options enlarge text/code and hide secondary notes without hiding the learning intentions. The pause/help screen does not contact a teacher: agree a private classroom help signal in advance. Reflection labels describe the current experience, not ability or a fixed learning style.

## Content and assessment

- Main focus: specification §3.2.1 — integer, real, Boolean, character and string.
- Python labels: `int`, `float`, `bool`, `str`. Python has no separate character type. General-type questions distinguish a suitable type for a stated requirement from the type of an existing Python value.
- Reading adapted and clarified from the Student Book, printed pages 16–17 / PDF pages 20–21. Added scenarios are not presented as textbook quotations.
- Explicit model explains `<class 'int'>` and nested function calls. No class programming is taught.
- Python `input()` is observed to return a string. Conversion, conditions, loops and `len()` are not required.
- Selected answers receive specific feedback and may be revised. Checked attempts are saved. Written explanations, screenshots and pasted code are **not automatically marked**.
- Count of correct checked selections is not a lesson grade or a mastery percentage. The full course AO framework is not reduced to recall/apply/justify badges. Teachers inspect the developing, testing and repairing evidence relevant to AO3.
- Extension solutions and teaching notes are available in teacher preview. Each challenge includes a second test. Extension 7 checks actual types, because its printed values alone cannot prove correctness.

## Student and teacher use

Students enter a name and class. Enter `teacher` as the name, leaving class blank, for preview, example answers and solution notes. Preview is not secure staff authentication. Students can navigate between all stages; they are not locked out for needing help or leaving a response blank.

Teacher demonstration work is separate. The Clear preview work control removes only this version’s teacher-preview data, after confirmation. It does not clear student profiles.

## Saving, images and PDF evidence

- Responses, preferences and checked attempts are saved to this browser’s local storage, scoped to the lesson and profile. Images use a separate lesson-specific IndexedDB database.
- This is **device-local**, not a cloud LMS or live teacher dashboard. Use the same browser/profile, name and class to resume. Clearing site data, changing browser or changing the site origin can make saved work unavailable. Name/class entry is not authentication; use separate browser profiles on shared devices.
- PNG, JPEG and WebP images up to 15 MB each can be chosen, dropped or pasted. Original image files are kept without resizing or JPEG conversion. Failed storage is reported; a temporary image remains available in the open page for export.
- PDF export is available throughout. It gathers all lesson stages, including unfinished work; selected answers and checked attempts; Types of Learning and Learning Pit Stop reflections; written work; pasted code; attempted extensions and their briefs/tests; evidence images; and Teams instructions.
- Unattempted extensions are labelled optional, not failed. The report contains final saved responses and checked attempts, not every keystroke or actions taken in another app.
- Export waits for image uploads and image loading. It requests the browser’s Print / Save as PDF dialog. Check the actual saved PDF before submission; printing is not automatic submission.
- In Teams: open the correct assignment → Add work → upload the PDF → Turn in → check confirmation. Keep the Python file as well.
- Earlier v1 responses under the matching old profile key are preserved separately in a report appendix. Old screenshot storage lacked a lesson identifier: any old images must be reviewed and explicitly selected on the plenary page before inclusion. Existing older browser data is not erased.
- Unreadable saved data is not overwritten by a fresh session. A warning asks the student to keep the page open and export current work.

Raleway is requested from Google Fonts; if unavailable, the browser falls back to Arial/sans-serif. The lesson itself does not depend on external scripts. Code uses a monospaced font.

## Validation and classroom check

Content and non-browser DOM tests cover feedback, revised attempts, profiles, reflection capture, navigation, teacher preview, image inclusion, long/inert code in reports, storage warnings and prior-version preservation. The supplied Python example solutions were executed and their displayed sample outputs checked.

The local browser preview was unavailable, so these checks are **not a visual browser audit**. Before teaching, preview on the actual student devices: use keyboard navigation and 200% zoom; try an image upload and reload; export a PDF containing a long program, long answer and several screenshots; inspect page breaks and image readability. Browser print behaviour and IndexedDB are browser-dependent.

Deployment remains manual. This revision does not push commits, deploy a live site or change hosting settings.
