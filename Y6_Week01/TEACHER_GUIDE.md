# Teacher guide and pedagogical review

## 60-minute lesson shape

| Phase | Time | Purpose | Evidence |
|---|---:|---|---|
| Learning briefing | 3 min | Make WAGBA, vocabulary and success visible | Pupil can state the two lesson strands |
| Do Now | 6 min | Activate Start–Work–Finish routines | Three checked responses |
| Main Activity 1 | 15 min | Apply routines to folders and filenames | Scenario explanation, folder path, filename and optional screenshot |
| Main Activity 2 | 25 min | Predict, build, test, modify and explain Scratch code | Predictions, testing checks, purposeful change, explanation and optional screenshot |
| Fast Finisher Hub | As available | Deepen or transfer learning after the core tasks | Up to eight recorded levels; target of three for fast finishers |
| Plenary | 6 min | Retrieve, transfer and self-assess | Two checked concepts, input/output explanation, confidence and next step |
| Transitions | ~5 min | Sign-in, moving between tabs, saving and export | — |

## Why the journey was changed

The previous mission-map structure split a single 60-minute lesson into too many destinations. It placed navigation decisions and game mechanics ahead of the learning. This version uses four compulsory lesson stops and one optional hub. Within a stop, pupils see one card at a time and receive a single primary instruction.

The card sequence follows a consistent teaching pattern:

1. teach or model the idea;
2. ask a focused check;
3. apply it in a real task;
4. explain the reasoning;
5. capture proportionate evidence.

Previous/Next changes the card and positions the next card below the fixed header. It does not return pupils to the landing page or ask them to choose another location.

## Instruction review

### Do Now

- Aisha’s short classroom story now establishes a recognisable beginning, working period and ending before any questions appear.
- Each phase uses complete sentences and explicitly explains why the actions matter; pupils are not asked to memorise an unexplained list.
- The visual acts as an overview while the narrative supplies context and cause, avoiding simple duplication.
- “Which phase?” questions use familiar actions and explicitly explain the purpose of the routine.
- The final question checks sequence, not recognition of an isolated word.
- Three questions are enough for a six-minute retrieval starter; longer typing is deliberately avoided here.

### Main Activity 1

- “File” and “folder” are defined before the hierarchy task.
- The folder path moves from broad to specific and inserts the pupil’s own name at the final level.
- The real-computer task is five short imperative steps. A screenshot is useful evidence, but direct teacher checking remains available for pupils whose device or workflow makes capture difficult.
- The filename question compares plausible examples. It explains the role of identifiers and versions rather than implying that one arbitrary naming convention is universally correct.
- The explanation prompt checks why organisation matters. Completion is not awarded for opening boxes or clicking through.

### Main Activity 2

- Scratch interface vocabulary appears at the point of use, supported by the annotated visual.
- Pupils predict before opening Scratch. This keeps the prediction genuine and makes the later comparison meaningful.
- Input and output are assessed separately. This catches the common misconception that movement is an input or that the key itself is an output.
- The build task contains only three code blocks. This reduces transcription load while preserving the event–instruction–output relationship.
- Testing asks pupils to observe both movement and message, then diagnose a missing output from evidence.
- The modification is purposeful: input, sign and message must remain consistent. Pupils explain the causal relationship rather than merely stating that something changed.
- The evidence model shows what a useful screenshot contains and includes a privacy reminder.

### Plenary

- Two questions retrieve organisation and coordinates.
- One explanation transfers input/output language to the pupil’s own program.
- Confidence options describe the support needed rather than labelling ability.
- The final next-step response gives the teacher actionable planning evidence.

## Challenge and extension progression

Extensions open only after both main activities. They do not replace unfinished core learning.

| Level | Cognitive demand |
|---|---|
| O1 Routine Rescue | Apply classroom routines to new scenarios |
| O2 Folder Detective | Interpret hierarchy and classify file/folder locations |
| O3 Filename Editor | Evaluate and justify a naming convention |
| P1 Two-Way Controls | Apply opposite signs on the x axis |
| P2 Four-Way Controls | Generalise movement to both axes |
| P3 Coordinate Mission | Compose and compare shortest algorithms |
| P4 Debug Detective | Infer likely bugs from incorrect outputs |
| P5 Design a Mission | Create constraints, an algorithm and a checking method |

Fast finishers are prompted to complete at least three levels. More advanced pupils can move beyond adding blocks into diagnosing, justifying and designing.

## Multilingual and literacy support

- English, Bahasa Melayu and Simplified Chinese support can be selected without changing the objective.
- The selected language provides a concise translation of the core direction and a bilingual keyword bridge.
- English Computing terms remain visible because pupils will encounter those terms in Scratch and the curriculum.
- Guided mode offers MCQs, word banks and sentence frames. Independent mode removes the word-bank prompts but keeps the same conceptual checks.
- Read-aloud uses the browser’s available voice for the selected language. Voice availability varies by school device.

Translation is a scaffold, not a substitute for teacher checking. Schools should adjust phrasing if their established subject terminology differs.

## Visual review

- Every image is placed immediately before the task it supports.
- All images have descriptive alternative text and a caption.
- Selecting an image enlarges it without losing the current activity.
- Corrected versions of the testing/debugging cycle and two-way-controls visuals are used.
- Text repeats every essential relationship, so an image is never the only route to the answer.

## Formative assessment points

- Starter: routine phase and sequence.
- Main 1: safety purpose, hierarchy, filename quality and real organisation.
- Main 2: workspace vocabulary, prediction, input/output, debugging diagnosis, purposeful modification and causal explanation.
- Extension: transfer from recognition to design.
- Plenary: retrieval plus confidence/next-step evidence.

Incorrect MCQ responses receive a prompt to re-read the clue or visual. They do not reveal the correct letter immediately. Correct responses explain why, supporting self-correction and vocabulary development.

## Before teaching

1. Check that the Scratch editor URL in `js/config.js` opens on the school network.
2. Decide whether pupils will sign in to Scratch or save projects locally under the school’s usual policy.
3. Demonstrate how to keep the lesson tab open while Scratch opens in another tab.
4. Confirm where pupils should create the Year 6 folder path.
5. Test browser printing and the Microsoft Teams assignment from a pupil device.
6. Remind pupils to exclude names, email addresses and unrelated tabs from screenshots.

## Accessibility checks completed

- Keyboard-operable buttons and choices
- Visible focus indication
- Large targets and high contrast
- No colour-only instructions
- Alternative text and enlarged-image view
- Responsive layout without horizontal overflow at 768 px
- Optional read-aloud and language support
- Teacher-check alternative to screenshot upload
- No forced animation and respect for reduced-motion preferences
